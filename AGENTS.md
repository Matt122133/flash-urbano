# Agent Instructions

The entry point into this repository for any coding agent. `AGENTS.md` is the
cross-agent standard; `CLAUDE.md` symlinks to it. This repo runs the harness as
a governance layer over spec-kit; see
[ADR speckit-harness-integration](docs/decisions/speckit-harness-integration.md).

## Project constitution

The project constitution at `.specify/memory/constitution.md` is the
highest-authority document in this repository. Every spec, plan, task, and code
change MUST comply with its principles. If anything in this guide conflicts with
the constitution, **the constitution prevails**. When collaboration or
architecture rules change, keep `AGENTS.md` and its `CLAUDE.md` symlink in sync
with the constitution (and `.github/copilot-instructions.md` if present).

The harness is the *process* layer beneath the constitution: it adds the
`covers:`/`verify:` controls and the human draft→active plan gate that spec-kit
lacks. It does not author, override, or delete the constitution.

## Operating principle

**If it is not in the repo, it does not exist.** Anything the agent must reason
over must live as versioned markdown, code, or schema inside this repo.

## Hard constraints (MUST / MUST NOT)

- **MUST NOT** write code without an approved spec-kit plan at
  `specs/<feature>/plan.md` with `status: active` and `analyzed:` filled. A
  direct instruction ("add X", "fix Y") is the brief for
  `/speckit-specify`, not approval to implement.
- **MUST** treat plan approval as explicit and plan-scoped. Answering
  clarifying questions, acknowledgement, or silence is not approval. After any
  clarifying exchange, restate what changed and ask for approval; then wait.
- **MUST NOT** edit files outside the active plan's `covers:` during
  execution. If a needed change falls outside, stop and choose: extend
  `covers:`, log it to [`docs/tech-debt-tracker.md`](docs/tech-debt-tracker.md),
  or drop it. Before each Edit/Write, verify the target path prefix-matches
  `covers:`.
- **MUST NOT** create a second `specs/<feature>/plan.md` at `status: active`
  while one exists in the current worktree. On an approved override, demote or
  complete the displaced plan and record the pause in that plan before opening
  the new one.
- **MUST NOT** perform opportunistic refactor or cleanup outside the plan's
  stated steps until `verify:` shows green.
- **MUST NOT** hand-edit generated spec-kit skills under
  `.claude/skills/speckit-*` or `.agents/skills/speckit-*`. They are
  regenerated by the `specify` CLI. The harness's own hook skills
  (`harness-gate`, `harness-verify`, `harness-loop`, `harness-implement-lite`)
  are the editable adapters.
- **MUST** surface any user instruction that conflicts with a hard constraint
  or phase gate before complying.

## Phase gates

Work moves through four phases:

- **Brief** — `/speckit-specify`, then `/speckit-clarify`.
- **Decide** — ADRs in `docs/decisions/` when a choice is hard to reverse,
  surprising without context, and a real tradeoff.
- **Plan** — `/speckit-plan`, `/speckit-tasks`, `/speckit-analyze`; the output
  remains `status: draft` until a human promotes it to `active` and fills
  `analyzed:`.
- **Execute** — `/speckit-implement`, `verify:`, `/speckit-converge`, looped
  until converged and green or until the loop cap emits remaining work. For a
  small active/analyzed plan, `harness-implement-lite` may execute the plan steps
  directly; `covers:` and `verify:` remain the controls.

Gates:

- No code without one active, analyzed `specs/<feature>/plan.md`.
- No edits outside that plan's `covers:`. `scripts/harness/check_plan_coverage.py`
  enforces this at pre-commit *when wired* — run
  `python3 scripts/harness/check_plan_coverage.py --doctor` to check whether it
  actually is in this clone; if `UNWIRED`, treat the rule as convention only
  until fixed (see `docs/HARNESS-TODO.md`).
- Not done until the plan's `verify:` command is green.

## On receiving a task

Classify before reading code or writing anything. Your first response states
the classification and the next artifact.

1. **Change-producing** — modify/add/fix/implement/refactor. Enter the harness
   at Brief. First artifact: `specs/<feature>/spec.md`.
2. **Investigation-only** — a question, audit, or exploration. Skip the
   harness; read and report. If it uncovers work worth doing, re-classify.
3. **Trivial** — typo, docstring, obvious rename with no behavioral impact.
   Proceed, but say "trivial - no plan" so the user can redirect.

If in doubt between change-producing and trivial, treat it as change-producing.
If the user wants to skip the harness, they must say so explicitly.

## Session bootstrap

Before producing substantive output, the agent:

1. Reads `.specify/memory/constitution.md` — the supreme document.
2. Reads `AGENTS.md`.
3. Reads `docs/README.md`.
4. Scans `specs/*/plan.md` for `status: active`. If a plan is present, read
   its `covers:` and keep the prefix list in working context.
5. Scans `docs/decisions/`.
6. Reads [`ARCHITECTURE.md`](ARCHITECTURE.md) before touching code; checks
   [`docs/tech-debt-tracker.md`](docs/tech-debt-tracker.md) if the task area
   overlaps open debt.
7. Best-effort harness-version check: read `.harness-version`. If
   `~/.claude/skills/init-harness-speckit/VERSION` is reachable and greater,
   surface: "This repo is behind init-harness-speckit `<VERSION>`; run
   `/init-harness-speckit` to sync."

## Where to save outputs

| Output | Folder | Naming |
|---|---|---|
| Feature specs and active plans | `specs/<feature>/` | `spec.md`, `plan.md`, `tasks.md`, generated design docs |
| Architectural decisions (ADRs) | `docs/decisions/` | `<slug>.md` (slug = `id:` frontmatter; see ADR adr-slug-canonical) |
| Process guidelines, runbooks | `docs/processes/` | `<topic>.md` |
| Tech debt | `docs/tech-debt-tracker.md` | append-only; new rows at top |

On completion, set `specs/<feature>/plan.md` to `status: completed`. After
creating any doc, add a one-line entry to `docs/README.md`.

ADR identity and format: see
[ADR adr-slug-canonical](docs/decisions/adr-slug-canonical.md).

## Working relationship

- No sycophancy. Be direct, matter-of-fact, concise.
- Be critical; challenge reasoning.
- No timeline estimates in plans.
- Don't add yourself as a co-author to git commits.
- On "we're done" / "close out", run the Session-exit steps in
  [`docs/processes/harness.md`](docs/processes/harness.md).
